### 本次更新

- 左上角的 Yorunote 小字換成既有精靈眨眼 GIF，圖示為 28×28，置中對齊左側導覽列。

- 依裝置像素比設定解碼尺寸，以 RepaintBoundary 隔離圖示重繪；沒有量測 CPU 或耗電改善。
- 沿用原本的視窗拖曳、最小化、最大化、關閉操作及 Yorunote 資料目錄。這次沒有資料遷移或清除步驟。

## English

This preview replaces the small text at the upper left with the existing 28×28 animated elf, centred over the navigation rail. The tooltip and accessible name remain Yorunote. An inactive window or a reduced-motion request uses the existing static icon. Image decoding follows the device pixel ratio and a RepaintBoundary isolates logo painting; no CPU or battery improvement is claimed.

Window dragging, controls and the application-data directory retain their existing behavior. The original six-frame GIF is included unchanged; dependency declarations and the lockfile are unchanged.

Windows CI passed 10 focused tests. The extracted production executable was launched and normally closed. A separate acceptance entry point from the same source passed 10 initial-process and 3 restart checks for animation, native HTTP, QuickJS/onResponse, keyboard reading, five-page downloads, SQLite and offline reading after restart. The historic full test suite was not rerun.

A separate download check verified the product ZIP, checksum, all 54 manifest-listed files, 21 AMD64 PE files and the unchanged GIF. Only source-text comparisons normalised checkout line endings; internal package hashes used raw bytes. This publication reuses those verified files without rebuilding.

Download both attached files, close the previous app, verify the checksum, extract the complete ZIP and run `Yorunote/yorunote.exe`. Keep every DLL and the data directory together. The unsigned build has no installer and does not migrate or delete existing Venera data.

The user's earlier report covered preview .1; device acceptance of this .2 build remains pending. Embedded web login, all third-party sources, DPI, multiple monitors, long sessions and Windows ARM64 are not fully covered.
